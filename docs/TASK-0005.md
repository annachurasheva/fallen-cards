## Промпт кодеру (Дельта): Вариант Б — парсер с пакетной фильтрацией, прогрессом и корректным реестром

> **Контекст:** fallen-cards. Переход на Вариант Б: парсер сам фильтрует повторы, сам классифицирует, сам пишет в реестр. `check-input.js` остаётся диагностическим инструментом, но НЕ является обязательным шагом перед парсингом.
>
> **Проблема, которую решаем:**
>
> 1. Текущий парсер обновляет реестр ДО записи данных в CSV. При сбое реестр говорит «327 готово», а на диске пусто. Нужно: реестр обновляется СТРОГО ПОСЛЕ записи в CSV.
> 2. Нет индикации прогресса — пользователь не понимает, жив ли процесс.
> 3. Классификация должна быть по статусу (убит/погиб → fallen, всё остальное → unclassified), а НЕ по полноте данных. Парсер пишет ВСЁ, что пришло из ЦАМО, даже если запись неполная.
>
> **Задача: переписать логику парсера и лаунчера. Отдать файлы целиком.**
>
> ---
>
> ### СПЕЦИФИКАЦИЯ
>
> #### 1. Вход и выходные файлы
>
> - Вход: `.txt` файл со списком URL (путь передаётся аргументом).
> - Выходная папка: `data/processed/<базовое-имя-без-расширения>/`
> - Выходные файлы (имя = базовое имя источника + маркер):
>   - `<имя>-fallen.csv` — записи со статусом «убит» или «погиб»
>   - `<имя>-unclassified.csv` — все остальные статусы (пропал без вести, попал в плен, умер от ран, умер, пустое, любое другое)
>   - `<имя>-error.csv` — технические ошибки (таймаут, сеть, битый HTML)
>   - `<имя>-repeats.txt` — URL, которые уже есть в `processed_ids.txt`
>
> #### 2. Классификация
>
> - Поле `cause_of_death` содержит «убит» ИЛИ «погиб» → `fallen.csv`
> - Всё остальное (включая пустое) → `unclassified.csv`
> - Парсер НЕ оценивает полноту данных. Даже если в записи только `document_id` и одна буква вместо ФИО — она записывается. Факт: запись пришла по этому URL из ЦАМО → она должна быть сохранена.
> - Разбор полноты и качества данных — задача другого кода, не парсера.
>
> #### 3. Пакетная фильтрация (Вариант Б)
>
> - Парсер читает ВЕСЬ входной файл.
> - Сверяет все `document_id` с `data/summary/processed_ids.txt`.
> - Совпавшие → пишет в `<имя>-repeats.txt`, пропускает.
> - Новые → очередь на парсинг.
> - Выводит сводку: «Всего: 327 | Повторов: 10 | Новых: 317».
>
> #### Реестр: терпимость к отсутствию
>
> - Если data/summary/processed_ids.txt отсутствует или пуст на старте — это НЕ ошибка.
> - Код трактует реестр как пустой и создаёт файл при первой записи
>   (mkdirSync recursive + appendFileSync).
> - Никаких crash, никаких «file not found».
>
> #### Реестр: атомарность (гарантия от «327 без csv»)
>
> - id попадает в processed_ids.txt СТРОГО ПОСЛЕ того, как его строка
>   физически записана в CSV (fs.appendFileSync выполнен).
> - Ситуация «id в реестре, а csv нет» невозможна по построению.
>
> #### 4. Реестр и атомарность
>
> - Каждые 50 обработанных записей:
>   1. Сначала `fs.appendFileSync` в CSV-файлы.
>   2. Потом `fs.appendFileSync` в `processed_ids.txt`.
> - Записи из `error.csv` в реестр НЕ попадают (будут повторены при следующем запуске).
> - Реестр обновляется СТРОГО ПОСЛЕ записи данных на диск.
>
> #### 5. Прогресс и индикация жизни (каждая запись)
>
> - Для каждой обработанной записи парсер печатает строку в консоль:
>   ```
>   [14:32:05] 47/317 | Панов Василий Иванович | 1155979419 → fallen
>   [14:32:08] 48/317 | Сидоров Пётр Петрович | 551843141 → unclassified
>   [14:32:11] 49/317 | [ОШИБКА] | 551843142 → error (TIMEOUT)
>   ```
> - Формат: `[ЧЧ:ММ:СС] {текущий}/{всего_новых} | {фамилия имя} | {document_id} → {fallen|unclassified|error}`
> - Если ФИО пустое — писать `[без имени]`.
> - НЕ использовать слово «Убит/погиб» в консоли. Использовать `fallen` / `unclassified` / `error`.
> - НЕ использовать эмодзи. Проект мемориальный. Вывод строгий, деловой.
>
> #### 6. Итоговый вывод по завершении сессии
>
> ```
> Сессия завершена: links_id_658_Арма-Эли
>    Всего в файле:      327
>    Повторов:           10  → links_id_658_Арма-Эли-repeats.txt
>    Новых обработано:   317
>       Павшие (fallen):       289  → links_id_658_Арма-Эли-fallen.csv
>       Прочие статусы:         25  → links_id_658_Арма-Эли-unclassified.csv
>       Ошибки:                  3  → links_id_658_Арма-Эли-error.csv
>    Реестр обновлён:    314 записей (ошибки не в реестре)
> ```
>
> - Без эмодзи. Без слова «убит/погиб». Только `fallen` / `unclassified` / `error`.
>
> #### 7. Лаунчер `run-edge-obd.ps1` — индикация жизни
>
> - Скрипт запускает `parse-obd.js` и пробрасывает его `stdout` в консоль без буферизации.
> - Добавляет «сторож»: если от парсера нет вывода более 30 секунд, печатает:
>   ```
>   [14:32:45] Процесс активен. Ожидание ответа от obd-memorial.ru...
>   ```
> - По завершении печатает код возврата и общее время работы:
>   ```
>   [14:38:12] Процесс завершён. Код возврата: 0. Время работы: 6м 07с.
>   ```
>
> #### 8. Формат CSV (fallen / unclassified)
>
> - Заголовки: `Заголовок, nomer_fonda, nomer_opisi, nomer_dela, document_type, document_id, last_name, first_name, middle_name, date_birth, place_birth, date_death, rank, warunit, cause_of_death, primary_burial, current_burial, conscription_location, primary_url, notes, Дата`
> - «Откуда перезахоронен» → колонка `primary_burial`
> - «Место захоронения» → колонка `current_burial`
> - «Доп. информация» → колонка `notes`
>   Если поля на странице нет — колонка остаётся пустой. Парсер не додумывает значения.

> - Пустые поля остаются пустыми. Парсер не подставляет заглушки.
> - `Дата` = текущая дата обработки в формате `YYYY-MM-DD`.
> - Все файлы, которые пишет код: UTF-8 без BOM.
> - Чтение: UTF-8. Если внешний файл начинается с символа BOM (U+FEFF) —
>   он срезается при чтении как служебный символ (одна строка нормализации).
>   Режим utf-8-sig и прочие кодировки НЕ использовать.
> - Совместимость с Excel не требуется и не закладывается.
>
> #### 9. Формат `<имя>-error.csv`
>
> ```csv
> document_id,primary_url,error_type,error_message,Дата
> 551843141,https://obd-memorial.ru/html/info.htm?id=551843141,TIMEOUT,Превышено время ожидания 30с,2026-10-06
> ```
>
> - `document_id` может быть пустым, если не удалось его извлечь.
> - `error_type`: `TIMEOUT`, `NETWORK`, `PARSE_ERROR`, `EMPTY_PAGE`.
>
> #### 10. Формат `<имя>-repeats.txt`
>
> ```
> # Файл: links_id_658_Арма-Эли.txt
> # Дата проверки: 2026-10-06 14:32:01
