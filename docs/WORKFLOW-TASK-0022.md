## 3. Как файлы попадают в GitHub (исчерпывающий перечень)

**Путь 1 (основной).** Кодер показывает код в чате дашборда → Анна копирует → применяет в локальной копии репозитория → коммитит и пушит сама → коммит появляется в `develop`.
**Путь 2 (патч).** Кодер даёт unified diff в чате → Анна сохраняет в файл → `git apply` → коммит (Путь 1).
**Путь 3 (Publish, если кнопка дашборда оживёт).** Дашборд создаёт ветку/PR в репозитории Анны → файлы существуют как **не смердженный PR** → Анна мержит только после вердикта Qwen «годен». До мержа PR не является частью `develop`.
**Путь 4 (правки Анны).** Анна правит сама словари, docs, регламент → коммит.

**3.5. Запрещённые пути:** коммит в `develop` без вердикта Qwen (кроме п. 6.3); любое попадание кода в репозиторий мимо рук Анны; ручная правка зеркала `warunits-fallen-cards.json` в обход `sync-units-dict.js`.
**3.6. Фиксация:** после каждого коммита Анна сообщает hash в канал А; Qwen сверяет коммит на GitHub (чтение) и подтверждает: «hash соответствует принятому вердикту».

4.2. Кодер показывает в канале Б: код функций, **реальный** вывод прогона на данных Анны, подтверждение неприкосновенности исходников.
4.2.1. Песочница кодера (ред. 2) Кодер вправе клонировать публичный репозиторий в песочницу в режиме только для чтения или получать файлы web_fetch. Обязательный минимум («зелёный чек-лист» в отчёте): data/dictionaries/warunits-fallen-cards.md; data/dictionaries/burial_dict.json; scripts/generate-cards.js; docs/ARCHITECTURE.md; docs/WARUNITS-DICT.md; docs/TASK-0022.md с поправками; перечень путей принятых CSV из data/processed/**, использованных в прогоне. 
Запуски — только node в песочнице над реальными изменёнными скриптами.
Реимплементация логики в браузерном JavaScript (§4.2 доказательством
не является) допустима лишь как визуализация-приложение.

Отчёт по §4.2 — текстом в канал Б: код, вывод node, фрагменты артефактов,
контрольная арифметика (прогон и полный набор: 194 уникальных warunit)

## 5. Чек-лист приёмки (общий для всех шагов)

5.1. Никаких преобразований строк данных ЦАМО (`toLowerCase`, `replace`, `normalize`, схлопывание пробелов). `trim` существует только внутри извлечения (`extractors.js`, `csv-reader.js` — проверено, не добавлять заново).
5.2. Совпадение с вариантом группы — точное равенство по знакам.
5.3. Скрипты не создают группы и не выдают ключи; нет совпадения → `unit_key: null` + журнал кандидатов.
5.4. Имена карточек и slug не меняются (`ARCHITECTURE.md` §5).
5.5. Выводы только реальные; контрольная метрика шага 1: 194 уникальных warunit = «с ключом» + «null».
5.6. JSON-зеркало собирается только `sync-units-dict.js` из активного MD; варианты буквально, регистр как в MD; группы с ключом «— (оператор)» — как `key: null` и в индекс поиска не попадают.
