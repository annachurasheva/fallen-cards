# Учёт экспертных карточек: инструкция

Экспертные карточки приходят в виде CSV-файлов в `data/processed/experts/*.csv`
(например, `fallen.csv`, `other.csv`, файлы вида `2026-06-01__parser_mem2026.csv`,
`2026-06-01__other_mem2026_.csv`).

Чтобы эти карточки были учтены в общем журнале принятых в работу персональных
карточек, выполните шаги ниже. Скрипты **не изменяют** сами CSV — только читают их.

## 1. Положите новые CSV в папку

```
data/processed/experts/
├─ <любой_файл>.csv
└─ ...
```

Требования к CSV:
- первая строка — заголовки;
- обязательная колонка `document_id` (число);
- желательно наличие `primary_url` (URL карточки на obd-memorial.ru);
- допустим UTF-8 BOM, кавычки и запятые внутри значений (парсер это умеет).

## 2. Предпросмотр (ничего не записывает)

```bash
node scripts/register-experts.js --dry-run
```

Покажет:
- сколько CSV найдено в `data/processed/experts/`;
- сколько уникальных `document_id` будет добавлено в глобальный журнал;
- первые добавляемые id (с URL и именем файла).

## 3. Внесите в глобальный журнал

```bash
node scripts/register-experts.js
```

Что происходит:
- читаются все `data/processed/experts/*.csv`;
- собираются уникальные `document_id`;
- в `data/summary/processed_ids.txt` дописываются **только недостающие** id
  в формате `<id>	<url>` (как это делает `parse-obd.js`);
- повторный запуск ничего не дублирует.

## 4. Проверьте, что карточки учтены

```bash
node scripts/check-csv.js
node scripts/check-input.js
```

Оба скрипта печатают блок «Экспертные файлы: data/processed/experts»:

```
===== fallen.csv =====
   Всего уникальных document_id: N
   Уже в журнале файла: A
   Уже в глобальном журнале: B
   🆕 Новых к обработке: C
```

Пояснение строк:
- **Уже в журнале файла** — id есть в `<имя_файла>__processed.txt` рядом с CSV
  (локальный журнал конкретного файла).
- **Уже в глобальном журнале** — id есть в `data/summary/processed_ids.txt`.
- **Новых к обработке** — id нет ни в одном из журналов; после
  `register-experts.js` эта строка станет 0.

## 5. Когда ещё раз придут новые CSV

Просто повторите шаги 2–4. Скрипты идемпотентны: уже учтённые id не
добавляются повторно, а `check-*` покажут только действительно новые.

## Примечания

- Не удаляйте и не редактируйте `data/summary/processed_ids.txt` вручную без
  необходимости — это глобальный журнал всего проекта.
- Если нужно зарегистрировать только один файл (в текущей версии — все сразу),
  положите остальные временно в другое место или доработайте
  `register-experts.js` под флаг `--file=`.
- Скрипты рассчитаны на Node.js (ESM), запускаются из корня репозитория.
