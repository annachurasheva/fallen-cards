## 1. Спецификация Astro-страницы объекта захоронения (TASK-0010/0017)

Сохраняйте как `docs/SPEC-astro-burial-page.md`:

```markdown
# SPEC: страница объекта захоронения в Astro (TASK-0010/0017)

Координата: annachurasheva/fallen-cards · docs/SPEC-astro-burial-page.md · v1
Принцип: один канонический порядок полей — три потребителя: парсер пишет
колонки CSV в этом порядке, CSV хранит, Astro рисует строки в этом же порядке.
Пустые поля не рисуются (как в OBD). Никаких выведенных значений.

## Маршрут и данные

- Маршрут: /memorial/<object-key>/ (object-key: например batalnoe-82-454).
- Данные страницы: запись объекта (строка memorial_objects.csv по document_id)
  - персоны с тегом memorial-<object-key> (список захороненных).

## Шапка

Заголовок: «Информация о захоронении»
Строка под заголовком: «ID: <document_id>»

## Блок полей (канонический порядок, ярлыки дословно как в OBD)

1 Страна захоронения
2 Регион захоронения
3 Номер захоронения в ВМЦ
4 Место захоронения
5 Первичное место захоронения (условное: рисовать если непусто)
6 Откуда производились перезахоронения (условное)
7 Дата создания современного места захоронения
8 Дата последнего захоронения
9 Вид захоронения
10 Состояние захоронения
11 Количество могил
12 Захоронено всего
13 Захоронено известных
14 Захоронено неизвестных
15 Кто шефствует над захоронением

Правила рендера: две колонки (ярлык слева серым, значение справа), значения
литерально из CSV без преобразований; несколько значений в ячейке («; ») — как
есть; пустое поле — строка не рисуется.

## Блок «Список захороненных»

- Персоны с тегом memorial-<object-key>: ссылки на карточки персон.
- Строка-счётчик: «Всего по данным fallen-cards: N».
- Примечание: полный список OBD — по ссылке источника (не дублируется).

## Подвал

- «Страница источника» → primary_url (литерал).
- Ссылка на страницу тега memorial-<object-key> (штатная сортировка Astro).

## Запрещено

Нормализации значений; выведение отсутствующих полей; поля сверх источника;
автоподстановка дат/счётчиков; слияние условных полей в одно.
```

Коммит: `docs: SPEC-astro-burial-page v1 — канонический порядок полей страницы захоронения`.

## 2. Промпт Дельте: правки obd-edge-objects.js

> **Контекст:** fallen-cards, текущий HEAD. Файл `obd-edge-objects.js`. Шесть правок по спецификации ниже; отдача Code Tool Record, полный файл, без push; после файла — три строки.
>
> **1. Выход:** `OUT_DIR = <корень>/data/dictionaries/memorial_objects` (создать при отсутствии); `OUT_CSV = 'memorial_objects.csv'`. CSV объектов не лежит рядом с карточками персон и рядом со скриптом.
>
> **2. Колонки (порядок = канонический, 18 колонок):**
> `document_id, country_burial, region_burial, vmc_number, current_burial, primary_burial_object, rebural_from, date_created, date_last_burial, burial_type, burial_state, graves_count, buried_total, buried_known, buried_unknown, sponsor, primary_url, Дата`
>
> **3. Добыча полей:** добавить `primary_burial_object: getParamValue('Первичное место захоронения')`; `Дата` = дата съёма `YYYY-MM-DD`. `document_id` брать ИЗ ПОЛЯ СТРАНИЦЫ: сначала `getParamValue('ID')`, при пустоте — регекс `/ID:\s*(\d+)/` по тексту карточки; `href.match` как источник ID убрать. После съёма сверка: хвост URL равен document_id; не сошлось — строка НЕ в CSV, а в ошибки с обоими значениями.
>
> **4. Рандом запросов:** перед прогоном перемешать список URL (Фишер–Йетс, seed = Date.now(), seed печатается в итог); случайные задержки между запросами оставить (3–15 с); каждые случайные 8–12 запросов — дополнительная пауза 20–40 с; User-Agent выбирать случайно из 3–5 литеральных строк на запрос.
>
> **5. Компактный консоль:** одна строка на объект: `[i/N] id=<id> OK` или `[i/N] <url> ERR <причина>`; без эмодзи и построчных отчётов; итоговый блок: seed, ok, err, путь выхода, список ошибок (url + причина). Ошибки дополнительно дописывать в `memorial_objects-errors.csv` (url, причина, дата).
>
> **6. Сериализация:** пусто = пустая строка (не `[]`, не `null`); BOM и заголовок сохранить как есть.
>
> **Критерий приёмки:** `--dry-run` на двух URL (33118331, 1167839469): консоль не длиннее N+6 строк; в собранной строке 1167839469 присутствуют литерально: `хорошее`, `Администрация Батальненского сельского поселения Ленинского района Республики Крым`, `Ак-Монайские позиции` одновременно в `rebural_from` и `primary_burial_object`; `document_id` равен полю страницы и хвосту URL; порядок колонок = п.2; эмодзи в консоли отсутствуют.
>
> **Запрещено:** трогать парсеры персон, run-edge-obd.ps1 (кроме проброса порта, если нужен), иные скрипты и словари.
>
> **Тег:** `fix: obd-edge-objects — канонические колонки, ID из поля страницы, рандом запросов, компактный вывод`
