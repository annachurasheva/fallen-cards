# TASK-0014 — слой подготовки карточек: назначение ключей

Статус: в календаре, старт после приемки полного прогона и закрытия контура персон.
База: develop после коммитов ревизии документации.
Архитектура и модель ключей: `docs/ARCHITECTURE.md` (раздел 3). Схема CSV: `docs/CSV_SCHEMA.md`.

## Принцип

**fallen-cards не нормализует и не подменяет значения — он выдаёт ключи.**
Раскрытие ключей в полные значения делает Astro-генератор по словарям Astro-репо.

## Состав

1. Читает сырые CSV (fallen/unclassified всех сессий).
2. Для каждой записи назначает ключи:
   - `unit_key` — по warunit через units_registry (сопоставление по dict_keys);
     не распознан → `unit_unknown_<hash>` + запись в журнал предложений.
   - `location_key` (место рождения, призыва) — через locations_dict
     (когда он появится в Astro-репо, сюда придёт его зеркало только для чтения).
   - `burial_current_key` / `burial_primary_key` / `rebural_from_key` — через
     burials_current/primary + словарь объектов TASK-0010.
3. Строит frontmatter с ключами и slug `bitva-za-krym-1942-<источник>-<document_id>`
   (детерминированный; ФИО — только в title и H1).
4. Отказные логи (нет ФИО / нет document_id) — как в v1/v2/v3.
5. Вывод: `data/cards/<obd|pmn>-<document_id>.md` с ключами в frontmatter
   (префикс источника обязателен: пространства id у obd и pmn разные).
6. `units-report`: журнал нераспознанных написаний warunit → предложения
   Astro-репо; показывает, какие ключи уже выданы и какие — кандидаты на выдачу.

## Приёмка

Приёмка TASK-0014 **включает визуальные тесты до выгрузки на прод**:

1. Просмотр карточки в Astro dev (`mem-2026-soursecraft-site`) — frontmatter,
   раскрытие ключей, SCHEMA.
2. Превью OG-представления карточки в контуре `mem-ok-s-admin` — ведёт именем
   и отчеством, корректная разбивка длинных ФИО.

Оба теста — на контрольной выборке карточек, до прода. Без зелёных визуальных
тестов приёмка не закрывается.

## Регламент

Отдача Code Tool Record; приёмка ревьюером по GitHub + контрольный прогон.
