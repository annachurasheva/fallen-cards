### 1. Как соблюдается запрет на переиздание `<slug>` (защита SEO)

В вашей системе уникальным идентификатором (и основой для slug/имени файла) является `document_id` из ОБД Мемориал (например, `person-551198135.md`).
Чтобы случайно не "выбить" страницу из индекса, новый скрипт **обязан** иметь режим **идемпотентности**:

- Если файл `person-<document_id>.md` уже существует, скрипт **пропускает** его (или обновляет только технические поля, не трогая `title`, `url`, `date_death`).
- Имя файла никогда не меняется, если не меняется `document_id`.
- Это реализуется флагом `--skip-existing` (который должен быть включен по умолчанию).

### 2. Визуал (MD) vs Софт (JSON)

Вы абсолютно правы. Парсить Markdown-таблицу в Node.js на 25 000 записях — это медленно и ненадежно (ошибка в одной вертикальной черте `|` сломает весь парсер).
**Правильная архитектура:**

- **Единый источник истины для софта:** `data/dictionaries/warunits-fallen-cards.json` (массив объектов или словарь). Его читает `generate-cards.js`.
- **Визуал для оператора:** `data/dictionaries/warunits-fallen-cards.md`. Этот файл **генерируется** из JSON-файла отдельным скриптом (например, `node scripts/build-warunits-table.js`), чтобы вы могли удобно смотреть и править его в Obsidian/VS Code.
- _Если вы правите MD вручную_, должен быть скрипт-конвертер, который обновляет JSON на основе MD, либо вы правите сразу JSON (в VS Code это удобно с форматированием).

### 3. Механизм пополнения и синхронизации (масштаб 25 000+)

Вам не нужно маппить 25 000 строк вручную. Нужен конвейер:

1. **Режим сбора неизвестного:** Скрипт запускается с флагом `--collect-unknowns`. Он не создает карточки, а собирает все нераспознанные `warunit` и `burial` в файл `data/dictionaries/proposals/unknown-pending.json`.
2. **Ручная валидация:** Вы открываете `unknown-pending.json`, группируете похожие написания и один раз присваиваете им ключи (например, все варианты "157 сд", "штаб 157 сд" получают ключ `157-00-fallen-cards`).
3. **Синхронизация:** Вы запускаете скрипт, который переносит утвержденные маппинги в основной `warunits-fallen-cards.json`.
4. **Генерация:** Запуск `generate-cards.js` без флага сбора, который быстро штампует карточки, используя уже известный словарь.

## Контекст и критические требования
1. **Защита SEO (Slug):** Имя файла карточки (`person-<document_id>.md`) и ключевые поля frontmatter НЕ ДОЛЖНЫ меняться при повторном запуске. Перезапись существующих файлов запрещена по умолчанию.

2. Структура JSON должна быть оптимизирована для быстрого поиска:
   {
     "157-00-fallen-cards": {
       "name": "157-я стрелковая дивизия",
       "variants": ["157 сд", "штаб. 157 сд", "СКФ 157 сд"],
       "source_doc": "docs/TEXT/157-ya-strelkovaya-diviziya.md"
     }
   }
3. Модифицируй `loadDictionaries()` в `generate-cards.js`, чтобы она читала `warunits-fallen-cards.json` и `burial_dict.json`, а НЕ устаревшие `units_dict.json` / `unit_keys.json`.

Добавь флаг `--collect-unknowns`.
- Если он активен, скрипт НЕ создает карточки.
- Вместо этого он собирает все значения `row.warunit` и `row.primary_burial`, для которых не найден ключ, в файл `data/dictionaries/proposals/unknown-pending.json`.
- Формат `unknown-pending.json`:
  {
    "warunit": {
      "скф 157 сд": { "count": 261, "document_ids": ["551198135", "..."] },
      "157 сд": { "count": 371, "document_ids": ["..."] }
    },
    "burial": { ... }
  }
- Это позволит оператору видеть частоту встречаемости и пакетно присваивать ключи.

- `--force-unit-key=<key>` (принудительный ключ для всех записей в CSV)

- Парсит Markdown-таблицу.
- Перезаписывает `data/dictionaries/warunits-fallen-cards.json` на основе данных из таблицы.

### 💡 Как это решит ваши задачи на практике:

1. **Вы в безопасности:** Флаг `--skip-existing` гарантирует, что даже если вы случайно запустите скрипт дважды, он не перетрет существующие карточки и не сломает ссылки в поисковиках.
2. **Скорость и надежность:** Скрипт читает JSON за миллисекунды, даже если там 10 000 ключей. Markdown-таблица остается вашим удобным "пультом управления", который вы конвертируете в JSON одной командой (`node scripts/sync-units-dict.js`) после внесения правок.
3. **Масштабирование:** Когда вы загрузите новые 15 000 записей, вы не будете в панике искать неизвестные названия. Вы запустите:
   `node scripts/generate-cards.js --input=новый_файл.csv --collect-unknowns`
   Откроете `unknown-pending.json`, увидите, что "скф 157 сд" встречается 500 раз, один раз добавите его в `variants` ключа `157-00-fallen-cards`, запустите `sync-units-dict.js`, и все 500 карточек сгенерируются корректно.
