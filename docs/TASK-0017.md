> - `children` — массив unit_key детей; для фронтов и армий — прямые подчинённые соединения.
> - `composition_from_doc` (только у дивизий) — полный перечень частей по историческому документу: это «эталонный состав», с которым оператор сверяет написания в CSV.
> - `validation_issues` — список известных расхождений/описок (для журнала TASK-0011).
> - Данные брать только из docs/TEXT и отчёта TASK-0015; никаких домыслов.

> - читает `unit_hierarchy.json` + `unit_keys.json`;

> - проверяет: каждый `parent` из unit_keys существует в hierarchy;
> - проверяет: `children` в hierarchy соответствуют `parent` в unit_keys (двусторонняя связность);
> - выводит отчёт `data/dictionaries/reports/hierarchy-check-<время>.md` с тремя секциями: «Все unit_keys покрыты», «Проблемы связности», «Отсутствующие источники» (unit_keys без source_doc в hierarchy).
>

>
> **5. Обновить `data/dictionaries/README.md`:** добавить описание unit_hierarchy.json и build-unit-hierarchy.js.

> **Критерий приёмки:** `node scripts/build-unit-hierarchy.js` запускается без ошибок; отчёт показывает coverage ≥ 95% (большинство unit_keys имеют entry в hierarchy); все существующие ключи с source_doc в docs/TEXT отражены в hierarchy с правильным составом.
