## Да, это архитектурный дефект — признаю

В промте кодеру я прописал «merge-ом из всех файлов прогона» — аддитивное пополнение словарей без защиты от дубликатов. В результате:

- `burials_primary.json` — 70 ключей, но если два CSV с пересекающимися карточками прошли через нормализатор — счётчики (`count`) завышены.
- `compare-plates.js`, когда появится, будет считать «100 солдат с Корпечи» как «200», если один и тот же CSV попал дважды.
- Заявление в гос-органы с раздутыми цифрами — дискредитация проекта.

**Корень проблемы:** у каждой карточки ОБД есть уникальный `document_id` (например `551267195` — Бадалов Г.И. из файла). Это естественный ключ дедупликации, и его нормализатор не использует.

## Правильная модель (исправляем одной правкой)

Дедупликация на уровне `document_id`:

- перед обработкой CSV — читать уже существующий `__normalized.json` (если есть) и собирать set всех `document_id`;
- при обработке новой карточки — если её `document_id` уже в set, пропустить (с записью в `skipped.txt`);
- словари `burials_primary/current` **пересчитывать целиком** из итогового массива (не merge-ом), а не дополнять.

Тогда:

- сколько бы раз вы ни запускали нормализатор на том же CSV — результат тот же (идемпотентность);
- если один и тот же человек встретится в двух разных CSV (разные поисковики нашли его независимо) — он будет учтён один раз с пометкой «найдено двумя источниками» (это ценно, а не шум);
- в `source_urls` каждого места захоронения каждый URL тоже будет встречаться максимум один раз.

## Промпт кодеру

> **Контекст:** fallen-cards, HEAD текущий. Ничего не запускать, кроме `node --check` и изолированных smoke-тестов. Коммиты — не ты. Формат: Code Tool Record, `scripts/normalize.js` целиком.
>
> **Задача:** сделать нормализатор идемпотентным через дедупликацию по `document_id`.
>
> **Изменение 1.** Перед обработкой каждого входного CSV — если рядом уже есть `<базовое имя>__normalized.json`, прочитать его и собрать `Set` всех `document_id`.
>
> **Изменение 2.** При обработке строки CSV — если её `document_id` уже в set, не включать в выходной массив, записать в `<базовое имя>__skipped.txt` строку `document_id | last_name first_name | причина: duplicate_in_same_file или duplicate_in_existing_normalized` (перезаписывать skipped-файл перед записью, не дополнять).
>
> **Изменение 3.** Словари `burials_primary.json` и `burials_current.json` — **пересчитывать целиком** из итогового массива (без merge). Функция `collectBurials(cards)` остаётся, но вызов `mergeDicts` (если есть) удалить: словарь = прямая запись.
>
> **Изменение 4.** `source_urls` внутри каждой записи словаря — тоже `Set` (никаких повторов URL при повторных прогонах).
>
> **Изменение 5.** В консольном выводе добавить счётчик пропущенных дубликатов: `   ⏭️  Пропущено дубликатов (по document_id): N`.
>
> **Самопроверка:**
>
> - запустить normalize на `experts` с файлом `2026-06-02__parser_mem2026.csv` в папке;
> - повторно запустить ту же команду — в консоли должно быть «Пропущено дубликатов: X, где X = количество строк в CSV»;
> - счётчики словарей при повторном прогоне не растут;
> - `node --check` OK; в коде нет функции `mergeDicts` или эквивалента аддитивного слияния словарей.
>
> **Формат:** файл целиком + три строки: Изменено / Проверено / Не тронуто.

## Что это даст

После правки:

1. Можно держать в `data/processed/experts/` любое количество CSV-файлов от поисковиков с пересекающимися именами — нормализатор сам вычистит дубли.
2. Полная сверка на 600+ записей даст честные цифры.
3. В заявлении каждая строка будет сопровождаться `document_id` + `primary_url` — проверяемая запись на ОБД, не «счёт в вакууме».

## Порядок действий

1. Отправьте промт кодеру.
2. После коммита — пересчёт двух наборов:
   ```powershell
   node scripts/normalize.js --input=obd_primary_urls_2026-09-22-22-37-31
   node scripts/normalize.js --input=experts
   ```
3. Пришлите финальные счётчики обоих прогонов (карточек обработано / пропущено / уникальных мест).

И тогда — промт на `compare-plates.js`, который уже будет работать на честных данных.
