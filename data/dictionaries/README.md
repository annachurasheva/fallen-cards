# data/dictionaries — справочные словари для назначения ключей

Координата: `annachurasheva/fallen-cards` · `data/dictionaries/README.md` · 2026-10-07.
Роли репозиториев и модель ключей — `docs/ARCHITECTURE.md`.

## Назначение в этом репозитории

Слой подготовки карточек (TASK-0014) **назначает КЛЮЧИ** (unit / location /
burial / rebural), а не нормализует значения: сырые CSV схемы v03 пишутся
дословно из ЦАМО, раскрытие ключей в полные наименования делает Astro-генератор
по копиям словарей. Значения здесь используются только как основа для
сопоставления и выдачи ключа. Исходные CSV неприкосновенны.

## Роли файлов

- `units_dict.json` — «сокращение из ЦАМО → полное название» для колонок
  `warunit`; служит для распознавания формирования и выдачи `unit_key`.
- `unit_keys.json` — реестр ключей воинских частей (новая схема, без архивного
  мусора): на запись — `dict_keys` / `type` / `number` / `parent` + опциональный
  `history_note`; служебный блок `_operator_note` скриптами не читается.
  Архивные поля (children, camo_url, formation, disband, status_note,
  reference_url) отброшены — они принадлежат Astro-репо для раскрытия;
  norm-формулировки живут только в `units_dict.json`, связь через `dict_keys`.
  Источник ключей `unit-*`.
- `units_raw_list.csv` — **верстак систематизации `warunit`**: сводка всех
  написаний warunit из прогонов с частотами; на нём решается, какие написания
  сводить к одному ключу, а какие — кандидаты на выдачу нового ключа.
- `ranks_dict.json` — звания (справка при сверке `rank`).
- `burials_primary.json`, `burials_current.json` — захоронения: первичное
  и текущее; источник ключей `burial-*` для `primary_burial` / `current_burial`.
- `burial-objects.json` — словарь объектов TASK-0010 (Ак-Монайский перешеек),
  включая атрибут «дистанция от Корпечи».
- `plates_korpech_59.json` — плиты Корпечи (донор: `memorial-korpech-crimea`,
  ветка `qwen3-memorial`); признак «на плите» для downstream.
- `locations_dict.json` — **внешний импорт, только чтение**: формируется внешним
  процессом и импортируется готовым файлом — не удалять при наличии. Источник
  ключей `loc-*` (место рождения, призыва, перезахоронения).

Парсер (`scripts/parse-obd.js`) словари НЕ читает и НЕ изменяет.

## Пополнение словарей

Словари units*dict / unit_keys / burials_* — **рабочие инструменты
fallen-cards**: они живут и пополняются **здесь**, решением Анны-Ch по
предложениям отчёта units-report. Astro-репо (`mem-2026-soursecraft-site`)
получает **копии** словарей и раскрывает ключи при генерации карточек.
`locations_dict.json` — внешний импорт, только чтение.

### Цикл пополнения

1. `node scripts/units-report.js` — отчёт по написаниям `warunit`
   (частоты по персонам, структурированные кандидаты);
2. `proposals.json` — очередь кандидатов на выдачу нового ключа;
3. решение Анны-Ch по каждому кандидату;
4. правка словаря (`unit_keys.json` / `units_dict.json`) здесь, в fallen-cards;
5. коммит `chore: dictionaries — <суть> (<дата>)`;
6. Astro обновляет копию словарей.

При выдаче **структурированного ключа** (полк + дивизия) все `observed_values`
предложения добавляются в `dict_keys` новой записи реестра — тогда синонимичные
написания распознаются реестром и fallback-ключ исчезает при перегенерации.

### Путь предложений (units-report.js)

- `data/dictionaries/reports/units-<дата>.md` — все написания `warunit` с частотами
  (число уникальных document_id) и статусами: есть в `units_dict` / нет в `units_dict`
  / есть в `unit_keys`; группировка кандидатов по значению `units_dict`
  (одна часть = одно предложение); блок структурированных кандидатов «полк + дивизия»;
- `data/dictionaries/reports/proposals.json` — кандидаты на выдачу нового ключа
  (поле `structured` — пары «полк+дивизия», оба числа уже есть в реестре).

## Правила форматов JSON

- кодировка UTF-8 без BOM;
- только двойные кавычки;
- запятая после последней пары ключ-значение не ставится;
- проверка синтаксиса перед коммитом (например, jsonlint.com);
- имена полей схемы v03 фиксированы: `rebural_from` — зафиксировано с опечаткой,
  потребители используют именно это имя (`docs/CSV_SCHEMA.md`).
