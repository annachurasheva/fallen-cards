# REVIEW.md — ревизия словарей донора memorial-korpech-crimea (ветка qwen3-memorial)

Дата ревизии: 2026-10-05. Ревизия статическая: файлы прочитаны целиком из репозитория `annachurasheva/memorial-korpech-crimea`, ветка `qwen3-memorial` (commit f37aa55), по адресу `data/dictionaries/`. Ничего не запускалось, кроме проверки синтаксиса создаваемых файлов.

В каталоге донора найдены: README.md, units_dict.json, ranks_dict.json, plates_korpech_59.json, units_registry.json, burials_primary.json, burials_current.json, units_raw_list.csv. Все JSON-файлы прочитаны целиком. locations_dict.json в каталоге отсутствует (по README донора он импортируется внешним процессом и не ведётся в этом репозитории).

## 1. units_dict.json — словарь воинских частей

- Размер: 107 записей.
- Структура: плоский dict «сокращение из архива → полное название строкой». Ключ пример: «106 сд», «15 гв. сп 2 гв. сд», «133 иап КрымФ»; значение пример: «106-я стрелковая дивизия», «652-й стрелковый полк 404-й стрелковой дивизии Северо-Кавказского фронта».
- Исторические справки (1–3 абзаца): отсутствуют полностью — все значения однострочные нормальные формулировки; пустых значений 0 из 107 (доля пустых — 0%). Справки живут в другом файле — см. п.4 units_registry.json (поле history_note).
- Оценка готовности: готов как есть для переноса (plain key→value, UTF-8, без циклов и вложенности). Для карточек выбытий справок не требуется; при необходимости истории берутся из units_registry.

## 2. ranks_dict.json — словарь званий

- Размер: 25 записей.
- Структура: плоский dict «сокращение/архивная форма → полное звание». Примеры: «мл. сержант» → «Младший сержант», «политрук» → «Политический руководитель роты», «воентехник 1 ранга» → «Военный техник 1-го ранга». Включены специфические wartime-формы (политрук, батальонный комиссар, воентехники, интенданты, санинструктор).
- Оценка готовности: готов как есть. Покрытие — типовые звания Карач/Керчь-59; при прогоне OBD возможны новые сокращения — словарь пополняется по тому же формату.

## 3. plates_korpech_59.json — список плит Корпусной горки (Керчь, плита №59)

- Размер: 59 записей имён + метаданные (source, vmc).
- Структура: dict с тремя ключами верхнего уровня: source (строка-референс учётной карточки №1360, переоформление 03.09.2024), vmc («82-390/2014»), names — массив из 59 объектов.
- Формат записи: { n — порядковый номер на плите, rank_raw — звание сокращённо дословно («ряд.», «к/арм.», «мл. л-нт», «политрук»), fio — ФИО дословно с плиты (часто с инициалами, например «Абгарян А.А.»); опционально obd_url и verify — привязка к карточке OBD и статус сверки. Годов рождения/смерти в записях нет (0 из 59), поле «плита» не нужно — сам файл и есть одна конкретная плита №59.
- Оценка готовности: готов как есть для своей задачи (сверка имён на плите с базой персон). Требует лишь конвертации ключей под схему fallen-cards при переносе; содержательной доработки не требует.

## 4. units_registry.json — реестр структуры воинских частей (другой .json в dictionaries/)

- Размер: version 2, 6 узлов (unit-398-sd, unit-826-sp, unit-404-sd, unit-643-sp, unit-skf-front, unit-krymf-front).
- Структура: { version, units: { "unit-<slug>": { dict_keys[], type, number, parent, children[], camo_url, formation, disband, status_note, reference_url, history_note } } }. history_note у 5 из 6 узлов содержит фактические исторические справки (периоды действия, формирование, расформирование) — это и есть носитель «1–3 абзацев», отсутствующий в units_dict.
- Оценка готовности: готов как есть; переносить вместе с units_dict (связь через dict_keys).

## 5. burials_primary.json и burials_current.json — словари мест захоронений

- Размер: по 1 ключу верхнего уровня (primary_burials / current_burials), оба — пустые объекты {}. Реальных записей: 0.
- Структура (замысел по README донора): «место захоронения из CSV → нормализованное название для тегов/навигации».
- Оценка готовности: не подходит по наполнению (каркасы пусты). Перенести как каркасы, наполнение — из первого боевого прогона parse-obd.js (поля primary_burial/current_burial).

## 6. Объекты захоронений: словаря нет, создан пустой каркас; наполнение — после первого прогона parse-obd-objects

Словаря объектов захоронения (карточки «Информация о захоронении»: наименование, тип, адрес, координаты, регистрация, количество захороненных, список зарегистрированных) ни в memorial-korpech-crimea, ни в puppeteer-project не существует. Создан каркас fallen-cards/data/dictionaries/burial-objects.json: ключ obj-<slug>, поля object_id, name, location, registration {date, number}, registered_count, plates_1985_count, rebural_from_locations [], source_url. Наполнение — после первого прогона scripts/parse-obd-objects.js.

В нормализатор src/normalizers/location.js добавлена функция attachObject(burial, objectsDict): при совпадении «Место захоронения» персоны с name объекта (регистронезависимо, ё=е, пунктуация схлопнута) в запись подставляется object_id; поле rebural_from сохраняется дословно и при привязке дописывается в rebural_from_locations объекта (без дублей).
